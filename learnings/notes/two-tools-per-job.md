# Keep two tools for each job and drop the rest

After the December tests each job keeps a winner and a backup on a different credit pool. This note is where the picks are recorded, with the evidence that decides them.

## What happened

By 25 November we were paying for seven creative plans and testing five video tools, four routes to Nano Banana Pro and two ways to make a 9:16 cut. Every extra tool splits the takes, so no tool gets enough runs to prove itself, and each one needs its own prompt notes and quirks written up. Alex agreed on 25 November ("Do it all") that once the December tests are in, the budget goes to a winner and a backup for each job.

No picks are made yet. The table below fills in as each test is decided.

## What decides it

1. **The rule is written before the run.** Each test row on This week carries its rule (V1: highest of 15 on Print reads, Look holds, Motion looks real). A rule changed after the results are in doesn't count.
2. **Four takes a tool at least**, same prompt and references, because two takes of one prompt differ by 3 points on average (note `score-ai-pictures`).
3. **Keeper rate first.** Keepers (12 of 15 or more) divided by takes. Where a test has its own rule, that rule wins.
4. **Cost per keeper breaks a tie.** Credits spent, priced with the unit costs in `spend-credits-before-renewal`, divided by keepers. Within one keeper in ten, the cheaper tool wins.
5. **The backup sits on a different credit pool** where one exists, so a lapsed plan or an outage never stops the job. Second place takes it unless it shares the winner's pool.
6. **Who can run it counts.** If two tools tie on everything else, the one a thread can drive without Alex's hands wins (note `what-a-thread-can-drive`).

## What happens to a dropped tool

- It gets no new rows in My shots or Claude's shots for that job.
- Credits already paid for still get used before renewal, on mop-up rows only (Alex's use-every-credit rule).
- At the plan's next renewal Alex decides whether to keep paying. The renewal dates are in project memory.
- A dropped tool comes back only through a new test with a written question, for example a new model release. That test gets its own row on This week and its own decision.
