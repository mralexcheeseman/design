# Plan on Monday, make midweek, review on Friday

Claude plans the week on Monday morning, both of us generate Tuesday to Thursday, and Alex reviews everything in one sitting on Friday from the shot sheet's Friday review tab.

## What happened

Until 25 November, approvals arrived one row at a time in whichever thread asked. On 25 November the review found the Firefly rows unticked two days before 4,100 credits lapse, the week-of-23-Nov tests still unrun and 73 files in Results still without a score. Alex agreed a fixed week the same day ("Do it all").

## The week

| Day | Who | What happens | Where |
| --- | --- | --- | --- |
| Monday 07:32 London | Claude (scheduled check-in) | Reads four balances, adds new keepers to Cuts, posts the plan: lapsing pools, open cuts, tests due, Claude's rows waiting with their cost | This week tab, the check-in thread |
| Monday | Alex | One reply: "go" on the rows he wants run | The check-in thread |
| Tuesday to Thursday | Claude | Runs the rows Alex said go to, logs each run, adds the lesson to `learnings/` the same day | Claude's shots, Drive, Back Office |
| Tuesday to Thursday | Alex | Runs his own rows by hand, files named `<ID>-v<N>` into Drive | My shots, Drive "ODHC shot results" |
| Friday 09:17 London | Claude (scheduled pack) | Posts the review pack: counts and links for each block | A new thread in the project |
| Friday | Alex | Works down the Friday review tab in one sitting | Friday review tab |

Both scheduled tasks run in a fresh thread in the project. Their full instructions are in project files, `ways-of-working/`.

## What the plan books, in order

1. Mop-up rows for any pool that lapses within 7 days, so no credit goes unused.
2. Open cuts on heroes, best score first (note `one-hero-many-cuts`).
3. Tests due by their Answer by date (Tests block on This week).
4. New picture rows, only for hotels whose heroes have all four cuts.

## The Friday sitting

The Friday review tab reads the other tabs, so Alex types only where he already does:

1. Score this week's files (My shots).
2. OK the cuts made from each hero (Your OK on Cuts).
3. Give the go on Claude's rows waiting (Status on Claude's shots), which become next week's midweek work.
4. Decide any test that is due, and record tool picks (note `two-tools-per-job`).
5. Glance at next week's cuts, which Monday will book.

## The one exception

A pool that lapses within 48 hours with credits unplanned can't wait for Friday. The thread that spots it asks Alex straight away with one decision card.

## Lessons

| Lesson | Status |
| --- | --- |
| `one-sitting-review`: Batch approvals into one Friday sitting, read from one tab, instead of asking row by row through the week. | try |
| `monday-books-lapsing-first`: The Monday plan books the pool that lapses soonest before anything else. | tested |
